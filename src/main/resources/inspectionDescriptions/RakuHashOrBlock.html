Reports a { ... } that looks like a hash composer but will be parsed as a block.

Raku decides between the two by inspecting the contents. Some things that read as hash-like to a human — a placeholder parameter such as $^a, or a pair whose value mentions the topic $_ — force the block reading, so the value ends up being a Callable rather than the Hash that was probably intended. Use %( ... ) to be explicit.

This inspection additionally applies an information-level highlight to the { and } of a construct that is a hash composer, so the two readings are distinguishable at a glance. Disabling the inspection turns that highlighting off as well. 


say { :$^a };            # Taken as a block, not a hash

# Correct
say %( :$^a );
